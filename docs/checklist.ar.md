# قائمة تدقيق أمان لارافيل والذكاء الاصطناعي — إصدار 2026
## PHP 8.4 / Laravel 13

> تم التحديث: أكتوبر 2026. متوافق مع معايير OWASP Top 10 (2025)، وOWASP LLM Top 10 (2025)، ونظام حماية البيانات الشخصية السعودي (PDPL / سدايا).

---

## 1. قائمة ما قبل التطوير والبيئة الأساسية

- [ ] مراجعة وفهم متطلبات الأمان الخاصة بالمشروع
- [ ] إعداد بيئة التطوير باستخدام PHP 8.4+ و Laravel 13.x
- [ ] تأكيد أن إصدار PHP ليس 8.1 أو أقدم (حيث وصل إلى نهاية الدعم EOL)
- [ ] تأكيد أن إصدار لارافيل هو 11+ أو 13 (حيث وصل لارافيل 10 إلى نهاية الدعم EOL)
- [ ] فحص وتدقيق الاعتماديات والمكتبات دورياً عبر `composer audit --locked` في CI/CD
- [ ] حماية الفروع البرمجية الرئيسية والتوقيع المشفر للالتزامات البرمجية (Signed Commits)

---

## 2. المصادقة وإدارة كلمات المرور (Authentication)

- [ ] تطبيق سياسات كلمات مرور متقدمة — حد أدنى 15 خانة وفقاً لمعايير (NIST SP 800-63B)
- [ ] تشفير كلمات المرور باستخدام خوارزمية `Argon2id` بمحددات الذاكرة المناسبة
- [ ] حظر تام لاستخدام `md5()` أو `sha1()` أو `rand()` في أي إجراء أمني
- [ ] تطبيق تقنية مفاتيح المرور **Passkeys / WebAuthn (FIDO2)** كخيار أساسي لتسجيل الدخول بدون كلمة مرور
- [ ] تفعيل المصادقة متعددة العوامل (MFA / TOTP)
- [ ] حماية الجلسات وتجديد معرّف الجلسة (Session ID Regeneration) عند تسجيل الدخول
- [ ] ضبط الكوكيز بخصائص الأمان: `Secure` و `HttpOnly` و `SameSite=Strict`
- [ ] تطبيق نموذج الصلاحيات المعتمد على الأدوار عبر Laravel Gates & Policies

---

## 3. التحقق من المدخلات والحماية من الهجمات الشائعة

- [ ] التحقق من جميع المدخلات من جانب الخادم (Server-side Validation) باستخدام Laravel Form Requests
- [ ] استخدام الاستعلامات المجهزة (Prepared Statements / PDO) بنسبة 100% ومنع دمج النصوص في SQL نهائياً
- [ ] الحماية التلقائية من ثغرات XSS باستخدام محرك قوالب Blade الافتراضي `{{ $data }}` وعدم استخدام `{!! !!}` للبيانات غير الموثوقة
- [ ] الحماية التلقائية من تزوير الطلبات CSRF عبر وسيط لارافيل المعتمد `validateCsrfTokens()`
- [ ] فحص ملفات الرفع بدقة: التحقق من نوع MIME الحقيقي، الامتداد، وفحص الملفات من البرمجيات الخبيثة
- [ ] تخزين الملفات المرفوعة خارج المسار العام واستخدام أسماء عشوائية مشفرة

---

## 4. أمان واجهات البرمجة (API Security — OWASP 2023)

- [ ] التحقق من ملكية الكائن في كل طلب لمنع ثغرات BOLA / IDOR
- [ ] استخدام Laravel Sanctum 4.x أو Passport مع توكنات تنتهي صلاحيتها
- [ ] تفعيل الحد من معدل الطلبات (Rate Limiting) على كافة نقاط النهاية (Endpoints)
- [ ] التحقق من عناوين URL الخارجية بدقة لمنع ثغرات SSRF
- [ ] تشفير كافة الاتصالات عبر بروتوكول HTTPS مع دعم TLS 1.3

---

## 5. أمان الذكاء الاصطناعي وتطبيقات النماذج اللغوية (AI & LLM Security — OWASP 2025)

- [ ] **الحماية من حقن التوجيهات (Prompt Injection Defense)**: الفصل التام بين توجيهات النظام (System Prompt) ومدخلات المستخدم، وتحديد إطار البيانات عبر وسوم XML
- [ ] **حماية التكاليف والمفاتيح (LLM Key & Cost Security)**: حفظ المفاتيح حصراً في الخادم وضبط حدود يومية لاستهلاك التوكنات لكل مستخدم
- [ ] **عزل بيانات المستأجرين في RAG (Tenant Isolation)**: تطبيق الفلترة الصارمة لمعرّف المستأجر `tenant_id` عند مرحلة البحث واسترجاع المتجهات (Vector Search)، وعدم الاعتماد على تعليمات النموذج
- [ ] **حصر صلاحيات أدوات الوكلاء (Agent Tool Sandboxing)**: استخدام قائمة بيضاء صارمة للأدوات المسموحة، وطلب موافقة بشرية مسبقة للإجراءات الحساسة والمالية
- [ ] **مسار حجب وتطهير البيانات الحساسة (PII Redaction Pipeline)**: إخفاء وتشفير أرقام الهويات الوطنية، والبطاقات الائتمانية، والهواتف قبل إرسالها إلى خوادم الذكاء الاصطناعي
- [ ] **التحقق من مخرجات النموذج (Model Output Validation)**: معاملة كافة مخرجات الذكاء الاصطناعي كمدخلات غير موثوقة، واستخدام Structured Outputs مع التحقق من المخطط (Schema)

---

## 6. ترويسات الأمان والإعدادات المتقدمة (Security Headers & Hardening)

- [ ] ضبط `APP_DEBUG=false` تماماً في بيئة الإنتاج
- [ ] تطبيق سياسة أمان المحتوى (CSP) مع رموز مميزة فريدة (Nonces)
- [ ] تفعيل ترويسة HSTS مع خاصية التحميل المسبق (preload)
- [ ] إزالة ترويسة `X-Powered-By` وإخفاء إصدارات الخادم ولارافيل
- [ ] حذف ترويسة `X-XSS-Protection` القديمة نظراً لكونها متقادمة وتسبب ثغرات في المتصفحات الحديثة

---

## 7. الامتثال التنظيمي والأنظمة الإقليمية (نظام حماية البيانات الشخصية السعودي PDPL)

- [ ] **نظام حماية البيانات الشخصية السعودي (PDPL - سدايا)**:
  - [ ] تطبيق مبدأ تقليل البيانات (Data Minimization) واقتصار الجمع على الغرض المحدد
  - [ ] الالتزام بضوابط نقل البيانات الشخصية خارج المملكة والحصول على الموافقات النظامية
  - [ ] تطبيق خطة إشعار سدايا خلال 72 ساعة في حال وقوع أي تسريب أو اختراق أمني
  - [ ] توفير خيارات واضحة للمستخدمين لحذف وتعديل بياناتهم الشخصية
- [ ] **متطلبات هيئة الزكاة والضريبة والجمارك (ZATCA)**:
  - [ ] حماية وتشفير الشهادات الرقمية للأجهزة (CSID)
  - [ ] حفظ سجلات التدقيق المالي بسلاسل تشفير غير قابلة للتعديل أو التلاعب (Tamper-proof Cryptographic Hashes)
