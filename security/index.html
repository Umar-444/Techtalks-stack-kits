PLATFORM SECURITY STANDARD

Three-layer guardrails for autonomous coding agents.

When AI coding agents generate code at machine speed, static architectural guidelines are not enough. TechTalks enforces a deterministic three-layer defense system across every stack kit to guarantee supply chain integrity, zero credential leaks, and OWASP compliance.

OWASP Top 10:2025
Coverage matrix across every kit

ARCHITECTURE

The Three-Layer Security Model

Every kit implements defense-in-depth across the agent's context, the repository test suite, and the continuous integration pipeline.

LAYER 01 In-Repository

Kit Security Folders

Every kit ships with an embedded security/checks.json manifest and dedicated test suites (Pest, Pytest, or Vitest) verifying RBAC, multi-tenant isolation, SQL query safety, and input sanitization before any feature is considered complete.

Automated test assertions
LAYER 02 Continuous CI

Automated CI Scanners

GitHub Actions automatically execute Gitleaks secret detection, Semgrep static analysis rulesets for OWASP Top 10 vulnerabilities, Composer audit, and npm audit on every pull request. Flawed agent outputs fail CI immediately.

Gitleaks + Semgrep rules
LAYER 03 Agent Context

Rules Review Gate

Before any rule file (CLAUDE.md, .cursorrules, AGENTS.md) is distributed, it passes a multi-agent review gate to guarantee zero hidden instructions, zero prompt injection vectors, and zero data exfiltration channels.

Transpiled from single-source YAML
DEFENSE SPECS

Prompt Injection & Tool Sandboxing Rails

Coding agents operate with bash access, file writing privileges, and external API connectivity. Our single-source rules explicitly configure agent behavior to prevent high-severity failure modes:

Tool Sandboxing: Agents are instructed never to execute destructive commands outside local workspace roots, never to send outbound credentials via curl/wget, and to restrict package installation to pinned dependencies.
PII Redaction: In AI and RAG kits, all prompt assembly pipelines mandate regex-based token redaction before passing user data to external LLM providers (Anthropic, OpenAI, or local Ollama).
Structured Output Validation: All JSON responses from LLMs must pass runtime schema validation (Zod, Pydantic, or Laravel Form Requests) before being stored or evaluated.
