Secure Vibe Coding: The Checklist I Run Before Any AI-Built App Ships

Building applications with AI agents takes hours instead of weeks. But when AI writes 90% of your codebase, who is auditing the security invariants? Here is the exact secure vibe coding checklist I run on every AI-built repository before deploying to production.

Secure vibe coding is the practice of maintaining production-grade security, access control, and secret hygiene while leveraging autonomous AI coding agents to build software at high velocity.

Recent security scans across thousands of vibe-coded repositories revealed a startling statistic: over 35% of AI-generated web applications contained hardcoded credentials, and more than 60% missed basic object-level authorization checks. Why? Because language models are trained to satisfy the user prompt first. If you say "create a dashboard showing invoice history", the agent writes the SQL query that works—it doesn't pause to ask if tenant isolation or rate limiting was requested.

To solve this, I run this 6-gate verification checklist on every project before the first production deploy.

Gate 1 / Secret Scanning with Gitleaks

Agents routinely drop API keys, database connection strings, or JWT signing secrets into configuration files. Even if you revert the commit later, the secret remains forever in git history.

  • The Rule: Never commit code without running an automated entropy secret scanner.
  • The Check: Run Gitleaks across your entire git history:
gitleaks detect --source . --verbose --redact

In our Security Standards, Gitleaks runs in GitHub Actions on every pull request. If any developer or agent accidentally adds a secret, the CI build fails instantly before merge.

Gate 2 / Static Analysis with Semgrep AST Checks

Simple regex linters miss complex multi-line vulnerabilities. AST (Abstract Syntax Tree) checkers analyze how data flows from user input to database sinks.

semgrep scan --config p/security-audit --config p/owasp-top-ten

This single command catches:

  • Raw SQL interpolation in ORM queries
  • Missing CSRF tokens on state-changing endpoints
  • Insecure direct object references (IDOR)
  • Vulnerable third-party dependency usage

Gate 3 / Object-Level Authorization (BOLA Defense)

Broken Object-Level Authorization is the #1 vulnerability in modern APIs. An endpoint like DELETE /api/teams/{team}/members/{id} must verify:

  1. The authenticated user is an administrator of {team}.
  2. The targeted member belongs to {team}.
The Invariant: In Laravel, every controller method must execute ->authorize('update', ). In Next.js, every Server Action must query Supabase with Row Level Security (RLS) active.

Gate 4 / Input Validation & Type Boundaries

Autonomous agents often write controllers that parse ->input() directly into database creation calls. This allows malicious actors to inject unvalidated fields (mass assignment vulnerability).

The Fix: Demand explicit Form Request or Zod schemas:

// app/Http/Requests/StoreProjectRequest.php
public function rules(): array { return [ 'name' => ['required', 'string', 'max:255'], 'slug' => ['required', 'string', 'alpha_dash', 'unique:projects,slug'], 'budget' => ['required', 'integer', 'min:0'], ]; }

Gate 5 / AI & LLM Threat Defense

If your vibe-coded application integrates LLMs (such as a customer support bot or document analysis tool), the application inherits an entirely new attack surface:

  • Prompt Injection: Untrusted user input altering system instructions. Always delimit external user content with XML tags (<user_query>...</user_query>).
  • Token Cost Explosions: Rate limit every user and enforce maximum token limits per completion to prevent denial-of-wallet attacks.
  • PII Redaction: Filter phone numbers, credit cards, and email addresses before forwarding context to commercial LLM APIs.

Gate 6 / Rootless Container Isolation

Never let your production application run as root inside a Docker container. If a remote code execution bug is discovered in a PHP or Node dependency, running as root grants the attacker immediate takeover of the container environment.

# Dockerfile
USER nonroot:nonroot HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD curl -f http://localhost:8080/health || exit 1
