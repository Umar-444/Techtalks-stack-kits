9 Vibe Coding Mistakes That Break Production Apps (and the Rule That Prevents Each One)

Vibe coding lets you move from idea to running software at breathless speed. But when AI agents code without guardrails, subtle architectural flaws creep in. Here are the 9 vibe coding mistakes that break production apps, and the single-source rules that prevent each one.

Vibe coding—a term popularized by Andrej Karpathy to describe coding primarily by prompting autonomous AI agents rather than writing character-by-character syntax—has transformed how developers build software. You describe what you want, the agent writes the models and routes, and within minutes, you have a working interface in your browser.

It feels like magic. But when developers take these vibe-coded applications and deploy them to real production environments, a familiar pattern emerges: the app breaks. Not because AI models are stupid, but because language models optimize for local completion rather than global architectural coherence.

Here are the 9 most critical vibe coding mistakes that compromise production applications, along with the concrete engineering rules you can drop into your agent configuration to stop them permanently.

01 / The 800-Line God File

The Mistake: When you ask an agent to add a feature (e.g., adding billing or user profiles), the agent's easiest path is appending logic to the existing controller or component file. Over 5 turns, your initial 60-line controller balloons into an 850-line monolith containing database queries, PDF formatting, webhook handling, and inline validation.

The Rule That Fixes It:

# .cursor/rules/architecture.mdc / CLAUDE.md
- Invariant: No controller or action class may exceed 120 lines of code. - Single Responsibility: Extract complex workflows into dedicated Action classes under app/Actions/. - Automated Verification: ArchTest asserts class length and method count before commit.

Every TechTalks Stack Kit ships with pre-configured architectural tests (like Pest Arch or Jest structural checkers) that automatically reject bloated god-files.

02 / Context Drift Across Turns

The Mistake: By turn 12 of a session, the agent's context window contains hundreds of lines of conversational chatter. The agent begins hallucinating routes that were refactored earlier, changing database column names, or reverting previously patched bugs.

The Rule That Fixes It:

# .clinerules / CODEX.md / CLAUDE.md
- Source of Truth: Consult DESIGN.md for design tokens and kit.yaml for active dependencies. - Never rely on conversational memory for API endpoints; check routes/api.php directly. - Clear context and re-anchor with the Agent Bootstrap Prompt every 10 turns.

03 / Hallucinated Packages and "Slopsquatting"

The Mistake: AI models frequently hallucinate non-existent composer or npm packages that sound plausibly named (e.g., laravel-supabase-sync or fastapi-jwt-guardrails). Attackers register these hallucinated names on public registries with malicious code (an attack known as slopsquatting).

The Rule That Fixes It:

- Mandatory: Do not install external third-party dependencies unless explicitly listed in kit.yaml. - Lockfile Integrity: Always run package managers with frozen lockfile flags ( pm ci, composer install --no-dev).

04 / Skipping Authorization (BOLA / IDOR)

The Mistake: In a rush to make the UI work, the agent generates endpoints like GET /api/invoices/{id} that look up the invoice by ID but never verify that invoice.user_id === current_user.id. It works in local testing, but allows any user to view any other customer's billing data in production.

The Rule That Fixes It:

- Authorization Invariant: Every controller action MUST call $this->authorize('view', ) or evaluate a Policy before querying the database. - Tenancy: Scope all Eloquent / ORM queries to Auth::user()->tenant_id.

05 / Hardcoded API Keys & Secrets

The Mistake: To quickly test an OpenAI or Stripe API integration, the agent drops a literal secret string sk-proj-492... into the controller or config file, intending to "clean it up later." You commit and push to GitHub, and within 90 seconds, bots have extracted the key.

The Rule That Fixes It:

Never trust an agent's memory to clean up secrets. Enforce it through automated pre-commit hooks and CI gates:

# Pre-commit hook / CI pipeline gitleaks detect --source . --verbose --redact

In TechTalks Stack Kits, Gitleaks is pre-wired into GitHub Actions with zero configuration needed.

06 / Disabling CSRF & Using Untyped Inputs

The Mistake: When a POST form triggers a 419 Page Expired error during local testing, naive agent prompts often suggest adding the route to in the CSRF middleware. Or the agent reads inputs using ->all() without checking data types.

The Rule That Fixes It:

- Security Invariant: NEVER disable CSRF middleware on web routes. - Request Validation: All inputs must be typehinted through explicit FormRequest classes. Never use $request->all().

07 / Database Migrations Without Rollbacks

The Mistake: The agent writes an up() method in database migrations that drops columns or renames tables without implementing the corresponding down() method or handling foreign key constraints. If a production deployment fails midway, rolling back is impossible.

The Rule That Fixes It:

- Migration Invariant: Every migration must have an exact inverse down() method. - Verification: CI must execute rtisan migrate followed immediately by rtisan migrate:rollback.

08 / Unsandboxed Host Execution

The Mistake: Giving autonomous agents unrestricted shell access on your personal laptop. A slight path resolution error during a cleanup command can delete project directories or alter system dotfiles.

The Rule That Fixes It:

Run all agent tool executions inside unprivileged rootless containers:

docker compose exec app vendor/bin/pest

09 / The "Looks Good in the Browser" Trap

The Mistake: If the homepage loads, the forms submit, and there are no red errors on the screen, developers assume the build is done. But silent failures—memory leaks, unindexed database queries, race conditions—only surface under production concurrency.

The Rule That Fixes It:

The Evaluated Stack Kit Approach: Before declaring any vibe-coded feature complete, run the automated evaluation suite: 
agy eval --kit laravel-filament-postgresql --all-gates
5/5 automated gates must pass: manifest integrity, rule syntax, sandboxed skills, OWASP security scanners, and runtime smoke testing.

Summary: Vibe With Guardrails

Vibe coding doesn't have to mean amateur coding. When you pair the speed of autonomous AI coding agents with deterministic rules, turnkey containers, and automated security scanners, you get the best of both worlds: 10x development velocity without the production heartbreak.
